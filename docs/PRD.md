# ResearchFlow — Product Requirements

ResearchFlow is a reusable workspace for academic research teams. The permanent product identity is ResearchFlow and the permanent credit is **Developed by Micro Biz Tek**. Team names, logos and academic details belong to individual immutable workspace IDs.

The initial use case is a six-person ICST BAIT team studying machine learning sales forecasting and inventory decisions for small retailers, targeting a February 2027 symposium. No institution, people, findings, citations, dates or project content are seeded into real workspaces.

## Release scope

MVP 1 covers verified email accounts, password recovery, independent workspaces, branding, secure invitations, leaders/members/supervisors, editable phases, tasks, progress and audit history. This release deliberately stops at the review gate requested in the brief.

Success means a verified user can create a workspace, invite a second verified account, assign and track tasks, update branding and read only their own teams' records. Members can update their assigned task status; leaders approve completion. Supervisors have read access in this milestone. Academic deliverable approval is MVP 2.

## Later releases — not implemented

- MVP 2: realtime discussions, documents with immutable versions, meetings and supervisor review workflows.
- MVP 3: dataset governance, paper sections, notifications, evidence-linked reports/PDF exports, manual GitHub development links.
- MVP 4: broader release certification, accessibility/performance audits, account lifecycle and operational monitoring.

Task calendar, dependencies, subtasks, checklists, comments and attachments are tracked as follow-up scope. Current task views are board and list. Invitations generate links for leaders to share; no email delivery is simulated. Workspace logos use private Supabase Storage, not a research document repository.

## Experience

Navy, white and muted teal; responsive sidebar and mobile bottom navigation; accessible dialogs; form validation; errors and empty states; theme preference. Metrics come from records. Empty teams show zeros rather than fabricated examples.
